# 项目代理指令审阅与优化

审阅日期：2026-09-11。目标：让 GPT-6 Astra 在已授权范围内自主完成任务，减少重复确认、无关扩展和提前停止。只优化指令，不更改模型配置、业务代码或真实数据。

## 范围

完整审阅了项目 AGENTS.md、CLAUDE.md、UI-DESIGN-GUIDELINES.md，以及 .agents/skills/ 下三个项目 Skill 和三个参考文件。另读取 skill-creator 与 OpenAI Docs 作为本次编写依据；未修改系统/插件提供的全局 Skills，也没有宣称审阅全部已安装插件。

## 问题与处理

| 原规则/位置 | 可能造成的行为 | 调整 |
|---|---|---|
| AGENTS 红线的“必须先问”与“(跳过)”同时存在；verify 又自行解释成全部先问 | 普通修改反复要求授权 | 统一到 AGENTS 的授权章节，区分局部源码、真实数据和外部发布，删除歧义旁注 |
| AGENTS、CLAUDE 和 verify 各有 Git/批准规则，且内容不同 | 已说“上传”仍再问是否推送 | 明确定义提交/上传，已有明确授权不重复询问，工具批准仍保留 |
| “所有数据必须持久化”未区分临时状态 | 给简单筛选/预览多建表或持久化机制 | 限定为业务记录，不包括临时 UI/测试状态 |
| verify 要求每次前端 tsc + build，而 build 已含 tsc -b | 重复检查 | 默认 build；类型检查可用于快速诊断，不固定重复 |
| 任意后端修改全量 pytest；冗余脚本非零必须全修到绿色 | 把小任务扩大成全仓治理，迟迟不能完成 | 影响分级；本次回归必须修，无关基线有证据后记录，不擅自扩展 |
| 必须保留“已废弃”标记，同时脚本将它算失败 | 保留与清零互斥 | 检测结果分类，合法兼容保留不等于缺陷；不修改脚本来掩盖问题 |
| 小程序“改版必须先出 HTML 并确认” | 用户已定方案也会中途暂停 | 只有用户要方案时出候选；明确实现直接落地 |
| 小程序 SKILL 写死环境地址，API 参考却要求 envVersion 自动切换 | 恢复过时环境、错误连接或反复确认 | 不在指令里固定运行时事实，读取当前配置；用户已指定环境即有授权 |
| 所有 onLoad/onShow 首行 checkLogin；旧参考规定统一清登录 | 重复加载、游客页被强制登录、网络错误触发退出 | 限定需登录页面，遵循当前守卫/续期；区分网络、403、401 |
| UI“发现即改”“不要覆写默认值”“照抄结构” | 顺手改全站，盖掉用户已确定的布局 | 只改任务范围；用户参考优先；共享组件变更才核对影响面 |
| UI guide 表头字重 450 与仅允许 400/500 冲突；字号与 Skill 不同 | 任意选择一份，样式来回变化 | 视觉数值集中到 UI guide，Skill 保留实施约定 |
| CLAUDE 禁止预览截图，且小程序源码也必须 PC tsc/build | 无法核对视觉，却做无关验证 | 预览按需视觉检查，小程序使用自身语法/注册/编译核对 |
| AGENTS 内陈旧页面表、React 18 和大段历史记忆 | 将旧事实当现行指令，扩大上下文 | 保留目录导航，版本/路由从源码读取，历史不放进常驻操作规则 |

## 四项行为准则

- 自主性：已授权实现持续推进至范围内结果完成，不停在“可以继续”。不把“完成”解释成发布或修复整个仓库。
- 澄清：普通实现细节自行判断；真正影响业务口径、权限、目标或难以恢复的后果时才问。先做不依赖答案的安全工作。
- 批准：同一目标、同一动作已有授权不再重复询问。普通推送不含强推，写迁移文件不等于执行真实数据迁移。
- 完成：相关验证通过且没有本次回归即可收尾；环境受阻和未知失败明确列出，不假称通过，也不无限扩大测试。

## 情景核对

这是静态规则推演，不是模型运行成功率评测。

| 请求/情境 | 新规则要求 |
|---|---|
| “按钮再缩小 10px” | 局部修改、适度视觉/构建检查；不先交三稿，不整站清理 |
| “先给我三个方案，不要改” | 只提供方案/所需预览，不改业务源码 |
| “已选 A，按它改” | 直接实现，不再问一次定稿 |
| “上传 Git”且 remote/branch 唯一明确 | 核对相关差异并提交正常推送；不二次问授权，不强推 |
| 测试发现确定无关的旧失败 | 记录依据，不自动修全仓，不称全量通过 |
| 测试无法确认隔离数据库 | 暂停数据库写测试，做其他检查并报告准确阻塞 |
| “小程序切到本地” | 核对端与可达地址后执行；不改 appid，不碰正式数据 |
| 修改 Skills 文档 | 核对引用、frontmatter 和规则一致性，不跑业务数据库测试 |

## 依据与限制

遵循 skill-creator 的“假设模型已有能力、只保留改变决策的必要信息”原则，并参考 [OpenAI GPT-6 Astra 指引](https://developers.openai.com/api/docs/guides/latest-model) 中的自主完成、指令冲突与适度验证建议。这里只采用适合本项目的边界，不机械复制文档中的广泛授权或子代理建议。

这些项目文件不会覆盖系统/开发者指令、沙箱或工具批准规则。全局插件 Skills 可能仍带有更强流程要求，后续出现具体冲突时应说明来源并做局部修订，不能通过本项目文件承诺取消所有平台确认。
