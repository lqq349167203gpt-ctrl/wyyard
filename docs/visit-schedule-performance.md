# 邀约与课表读取优化

范围：PC 邀约、PC 课表及它们共用的备注读取接口。保留权限、卡次计算、课程/邀约保存和操作日志规则，不改业务历史数据或小程序环境。

## 改前依据

本机 Vite 开发服务、已登录的同一账号、2026-09-12、同一空间。浏览器网络面板原有 Disable cache 已开启、无网络限速。以下为单次轨迹观测，不代表正式服务器或稳定均值：

| 请求 | 观测 |
| --- | --- |
| 当天邀约 | 约16 KB，约480～850毫秒；同条件有重复读取 |
| 课表 dashboard | 约10 KB，两次请求约877毫秒、1.08秒 |
| 客户轻量目录 | 约368 KB，约515毫秒 |
| dashboard 后补客户 batch | 约109毫秒，页面等它返回才显示表格 |
| 课表三类案主余量 | 没有打开案主选择仍立即请求，约350毫秒/类 |

源码确认：课表加载态会卸载整个表格；重挂再触发案主余量、组织、排序和IP读取。两页首屏预载整份历史快照。课表完成计数逐课扫描当天相关的全历史备注并构造正文对象，邀约可见备注和汇总重复投影。

开发 StrictMode 会放大重复挂载；保留 StrictMode，通过现有在途读取合并解决同条件重复请求。只复用未结束的请求，不保存业务查询结果，写入后立即失效，按页面、日期/空间完整URL及账号权限隔离。

## 验收点

- 同一天邀约名单、到场状态、备注/下次跟进、课表各类型、参与者和完成计数与原口径一致。
- 备注按当天客户批量归集；取消/删除记录、课程备注与邀约备注共享、权限过滤保持原语义。
- 首屏不读取历史快照，不预取未使用的三类案主余量；实际展开或选人仍能正常读取。
- 同一天刷新不卸载表格，日期/空间切换中不能把旧记录保存进新上下文，旧响应不能覆盖新选择。
- 已加载的人员资料复用，只补缺失项；新增/编辑后的刷新不能复用写入前的在途结果。
- 验证先跑隔离 schema 中的备注、邀约、课表回归，再检查构建和同条件浏览器请求。不能仅用请求数量减少宣称达到100毫秒。

## 结果

已完成这批读取优化，未改业务数据、扣卡、权限或小程序环境，未提交 Git。

### 实现

- 两页同条件 GET 复用在途请求；客户简表保留原有专用缓存，不再叠加通用复用或在初始化时清掉其他在途读取。业务写入仍使读取失效。
- 邀约初始统计窗口直接跟随选中日期，去掉挂载时额外刷新；两页历史快照只在打开面板后读取。
- 课表同日刷新保持表格及未保存草稿，服务端同 ID 的更新仍会同步；切换日期／空间先刷入旧草稿，旧上下文在加载期间不可操作，过期响应不能覆盖新日期。
- 人员目录并行读取，已覆盖的人员不再批量补取；三类案主余量聚焦后才读，保存后强制刷新，不复用保存前请求。
- 当天完成数一次归集并给所有课程复用，不构造备注正文、不排序正文、不执行历史备注迁移。邀约备注可见性与汇总复用一次投影。

### 同条件复测

仍为本机开发模式、同账号／日期／空间、Disable cache、无网络限速。单次轨迹有机器负载和预热差异，不作稳定 SLA：

| 项目 | 改后观测 |
| --- | --- |
| 当天邀约 | 1 次请求，约454毫秒，约16 KB |
| 课表 dashboard | 1 次请求，约310毫秒，约10 KB；改前两次约877毫秒／1.08秒 |
| 课表客户目录 | 1 次 light 读取，约173毫秒；目录已覆盖，本次无 batch 补取 |
| 两页首屏历史快照 | 均未请求 |
| 课表首屏三类案主余量 | 均未请求 |

浏览器已核对9月12日2条、9月11日1条，日期切换期间旧表格受保护。没有在业务库编辑记录来做测试。尚未达到“全页100毫秒”的目标；客户目录约368 KB及其他统计读取仍存在，本批不扩展为目录协议重构。开发模式全部资源 Finish 不等于首屏可操作时间。

### 验证

- 前端3个定向文件共43项通过（最终补充项后仅重跑受影响文件）；生产构建及业务目录三端一致性检查通过。
- 后端备注、邀约、课表读取、下次跟进、权限、取消分组等定向测试82项通过、2项原有预期失败；修改文件 Ruff 通过。
- 两项失败位于 `backend/tests/test_visits.py:67`、`:133`，期待原始体验文字，而当前协作备注汇总返回“创建人：文字”。隔离执行本批修改前与修改后的汇总函数，两项输出相同，均带前缀；新增／修改的单笔响应也不走本批列表投影优化。未削弱断言或改动既有业务口径。
- 管理端小程序共用的轻量备注接口包含可见客户及备注权限回归；本批未修改小程序源码，未做真机端到端验证。
