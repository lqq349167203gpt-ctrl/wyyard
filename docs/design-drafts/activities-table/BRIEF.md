# 活动记录 tab 表格样式 — 设计简报（3 版方案）

## 背景与目标
PC 管理端「客户资料」客户详情页的「活动记录」tab（`frontend/src/pages/healing-records/components/detail-view.tsx` 第 464-501 行）当前是朴素的四列表格：日期（可带「未参加」灰标签）、活动名称（可带「公益」灰标签）、角色、课程老师（可空，空值显示 `-`），每页 5 条 + 底部分页条。

整个详情页正在向客户端小程序风格靠拢（详见 `docs/design-drafts/customer-detail/BRIEF.md` 视觉风格节）。本任务为该表格出 **3 版纯 HTML 样式参考稿**，只改视觉呈现，不改信息结构与交互逻辑（仍为 5 条/页 + 分页条），不改动任何线上代码。

## 关键场景：同一天多场活动（真实数据统计）
真实生产数据统计：**同一天 ≥2 场活动的记录占 60.8%，最多一天 4 场**——同日多场是常态而非特例，必须作为一等场景检验方案：

- V1 表格需升级「日期合并」处理：同日记录只显示一次日期（rowspan），组内行去掉分隔线，并加「当日 N 场」计数胶囊
- V2 时间线天然兼容：左侧一个日期节点，右侧纵向叠多张活动卡（日程 / agenda 形态），无需额外处理
- V3 紧凑列表保持原样则日期逐行重复，冗余感明显、无法归组

场景演示统一假数据：2026/07/15 周三一天 4 场——沙盘疗愈（参与者 · 沈青）、呼吸禅茶（参与者 · 苏禾）、读书会（参与者 · 老师未排，显示 `-`）、觉醒游戏【睿敏】（案主 · 沈青）。

## 视觉 token（沿用客户详情页改版规范）
- 页面背景 `#f4f5f6`，卡片 `#ffffff`，圆角 14–16px，柔和阴影 `0 2px 4px rgba(33,38,49,.05)`
- 主文字 `#212631`，次要 `#79838f`，弱化 `#a8b1bd`，占位 `#d0d3d6`
- 强调色：青柠 `#c9f24b`（配深橄榄绿文字 `#3d5500`）；选中态可用「黑底 #212631 + 青柠字」
- pastel 标签：`#dcf5e4/#157a3c`（绿）、`#e0ebff/#2f5cc4`（蓝）、`#ffe8d9/#c25a1b`（橙）、`#ece6ff/#6a48d8`（紫）、中性 `#f1f0ed/#79838f`
- 数字用 tabular-nums；中文界面；不要 emoji；图标用极简线条 SVG 或纯文字
- 字体：-apple-system, "PingFang SC", "Helvetica Neue", sans-serif

### 本表格的语义色约定（三版统一）
- 「公益」标签 → 绿 pastel（`#dcf5e4/#157a3c`）
- 「未参加」标签 → 中性（`#f1f0ed/#79838f`），视觉上降低该行的存在感
- 角色「参与者」→ 蓝 pastel（`#e0ebff/#2f5cc4`），「协助者」→ 紫 pastel（`#ece6ff/#6a48d8`），「案主」→ 橙 pastel（`#ffe8d9/#c25a1b`）
- 课程老师为空 → 弱化色 `-` 占位

## 三版设计方向
| 版本 | 方向 | 一句话说明 | 同日多场兼容性 |
| --- | --- | --- | --- |
| V1 · 精致表格 | 保留表格形态做视觉升级 | 改动最小、落地成本最低，适合快速上线 | 需加「日期合并」升级处理（rowspan + 组内去分隔线 + 当日 N 场胶囊），处理后紧凑清晰 |
| V2 · 时间线卡片 | 跳出表格，按时间轴排列活动卡 | 强调「客户的疗愈旅程」叙事感，呼吸感最强 | 天然按天分组，一个日期节点叠多卡，多活动日最从容 |
| V3 · 紧凑列表 | 高密度单行列表 | 信息密度最高，适合记录很多时快速扫读 | 差：日期逐行重复、无法归组，不适合该场景 |

三版均展示完整状态：表头（如有）、5 行数据（含一条「公益」标签、一条「未参加」标签、一条课程老师为空显示 `-` 占位）、分页条；另在三版之前设「同一天 4 场活动」独立对照区块，每个渲染块下方附极短点评。

## 选用建议（结论）
基于真实数据（同日 ≥2 场占 60.8%、最多 4 场/天）：

1. **推荐 V2 · 时间线卡片**：时间线天然按天分组，一个日期节点纵向叠卡，多活动日最从容；同时最贴小程序气质，叙事感强。同日多场占六成的数据下，这是与数据结构最匹配的形态。
2. **低成本替代 V1 · 精致表格 + 日期合并**：保留表格形态，仅对同日记录做 rowspan 日期合并与组内去分隔线，改动最小、与现有代码结构最接近。
3. **不推荐 V3 · 紧凑列表**：同日多场时日期逐行重复、无法归组，冗余感强；如未来单客户记录量极大，可考虑作为可选的「密集模式」。
