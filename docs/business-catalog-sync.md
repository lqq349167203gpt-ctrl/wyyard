# 第一批：类型目录统一与关联验收

本批边界：会员卡类型及新增默认值、沙龙技能学习类型及有效期、线下落地课程和 OH 卡诊断子类型，以及这些定义的筛选、详情、报表、导出、日志联动。统计算法、扣卡流水、权限规则和历史业务记录不在本批重写。

## 唯一维护入口

编辑 `shared/business-catalog.json`，然后运行：

```sh
python3 scripts/generate-business-catalog.py
python3 scripts/generate-business-catalog.py --check
```

生成后端 Python、PC TypeScript、管理端小程序 JavaScript 三份静态数据。现有 `payment-types` / `learning-course-types` 模块保留接口并从生成数据派生。PC 构建和小程序提审脚本检查是否漏生成；运行页面不增加请求，不读取仓库外文件，不新增缓存。

PC 的 `npm run build` 会自动检查目录一致性。小程序发布前须执行 `bash scripts/check-release.sh`，微信开发者工具直接点击“上传”不会自动运行这个脚本；当前本地开发态也不能视为已通过正式提审检查。小程序发布仍需上传对应版本，静态配置不具备绕过微信版本发布的热更新能力。

修改显示名称时必须检查旧值兼容；现有类型名称仍用于部分业务标识，不能只改 JSON 就假定历史键自动迁移。新增类型与默认值可从此统一分发，真正新增业务流程仍需实现入口与后端行为。

`count: null` / `duration_months: null` 表示新增时由录入人填写，不代表无限权益。默认值只用于新增选择，不用于覆盖历史次数或有效期。用户在系统内创建的沙龙类型、技能训练课程类型和其他项目仍从原有数据库读取。

## 历史配置的明确边界

旧升单档位可能把月卡、年卡等分在不同档。它们显示归为“定制化”后，无法从名称推断应放入体验／转化／升单／复购哪条新规则。本批不自动合并、保存或清空这些配置。需在现有规则配置页明确设置后才可验收该业务口径；此项不应标记为“已自动统一”。
