# 主理人：使用与统计口径

## 入口与权限

- PC：业务菜单「主理人」，路径 `/principal`。
- 管理端小程序：「我的 → 主理人」。客户端不增加页面。
- 角色管理：开启「主理人」页面，并配置「主理人组织查看范围」。
- 仅查看自己：通过账号归属人与客户姓名/昵称唯一匹配，取组织成员中的所属组织；同名歧义或无关联时不展示组织。查看所有：可选择全部或单个组织。
- 客户可见范围与交易权限同时生效。交易明细权限为 detail 才开放交易列表、转化分析；summary 只显示汇总，none 不展示交易指标。
- 所有接口（含导出）重新校验角色范围。保存的规则不保存授权，不可绕过权限。

## 四个板块

1. 经营概况：三张一级卡（成交量 / 课程数 / 引流人数）点开在卡片下展开该组的二级面板，默认展开第一张（成交量）；同一时间只展开一组。面板里每个维度是一个下拉（控件与自定义筛选同一套，菜单里带数量），一级维度（付费项目 / 课程类型 / 课程老师 / 引流人）互斥，子级（卡种 / 具体课程）挂在它的上一级下面，购买类型可与付费项目叠加；各下拉的选项数量按「其他维度」筛完再算（互相影响），重复点同一项不取消、要清掉这一维请选「全部」；筛选交给后端做，翻页口径一致。成交量＝成交量＋成交人数＋升单人（发生过升单的客户数，每人只算一次）＋升单量（同一人多次升单按次数累加）＋付费项目类型数（维度有付费项目、购买类型、卡种；购买类型可与付费项目叠加，选中项目后出现卡种下拉），列表为每笔成交记录（成交日期／客户／项目／成交归属／购买类型／成交笔数／成交人；购买类型旁问号解释首购、同类复购、跨品类首购、升单，成交笔数是该客户在当前筛选范围内的成交笔数，点这个数字会列出该客户在这批数据里的每一笔成交；导出左边可切换「每笔交易显示一次 / 同一人显示一次」，同一人时一个客户一行、日期取最近一笔、项目与成交人合并去重）；课程数＝课程数（按类型拆，选中类型后出现具体课程下拉，具体课程按课程名 + 所属组织区分）＋课时数＋上课人数/人次＋课程当日成交数（这门课的到场客户在开课当天的成交笔数）＋课程关联成交数（只算明确挂在这门课上的成交，比如这门课的粗门次卡扣卡记录；列表里「关联成交」那一列就是它），列表为课程记录（列：课程日期／课程／活动类型／课程所属／课程老师／课时数／案主／部位数／到场人数／新人名单／老人名单／当日成交／关联成交）；引流人数＝该组织/俱乐部所属人员带来的引流客户数（按引流日期落在统计周期内计入；卡片旁问号说明为「按照引流日期进行统计」）；客户档案「引流人」为空的统一归入「未配置」＋每位引流人的引流人数、引流客户成交笔数与各付费项目成交笔数；维度有引流人（含未配置）、跟进阶段、流量来源、客户标签（互相影响，可叠加），列表为客户/引流人/成交笔数/成交项目。面板底部汇总条跟着选中的维度走。
2. 课程记录：课程所属、老师、课时、案主、部位数、到场人数、首次/再次到场、后续关联交易，支持明细。
3. 交易记录：成交日期、客户、项目、成交归属、首购/同类复购/跨品类首购、成交人。粗门次卡扣卡按购买算，和会员卡等其他类型一样参与首购/复购/升单判断。无金额、支付方式。
4. 转化分析：配置起点与多个目标，任意/全部目标、首次/任意/再次、产品与具体卡种、观察天数、同组织或跨可见组织。筛选条件只加在起点侧，用于筛人（谁进这批人），字段/规则/取值与自定义筛选一致：性别、年龄、会员身份、跟进阶段、客户标签、流量来源、引流人、承接人、服务老师、引流日期、邀约日期；目标侧只描述「什么算转化」，不重复放客户条件。「再加一个目标」用于增加另一种到达方式。结果按已转化/未转化/观察中筛选，查看对应起点与目标明细。

## 关键定义

- 案主不算到场：觉醒游戏 / 情绪释放 / 能量结的案主单独出「案主」列，不计入到场人数，也不进新人 / 老人名单。
- 人数去重；一个人区间内多个起点，只取区间内第一个符合规则的起点。首次判定使用可见范围全部历史，不仅是当前日期区间。
- 起点日期受筛选区间限制；目标可发生在区间外，但必须在起点之后且在观察天数内。0 天为当天。
- 当天只能确认同日关联，不能证明活动导致了购买。源订单本身不能充当目标。
- 因历史仅记录业务日期，同日多单视作首购日，不根据录入顺序推断实际成交顺序。「再次」指非首次日。
- 截止日当天仍在观察期，次日才进入完整观察期分母。页面同时展示全队列转化率与完整观察期转化率，按北京时间判断今天。
- 能量结没有课时：课时记 0，它按「部位数」结算（部位数来自付费项目里能量结的购买部位数），列表里显示在「部位数」列。
- 升单（信息配置 → 升单配置）：先把若干付费项目归成「大类」并取名（付费项目的顺序与「付费项目」页面一致；会员卡可选到卡种、内部课程可选到课程类型、其他项目可选到具体项目），再给这些大类排序，顺序就是升单方向；大类里可以只挑会员卡的某个卡种（会员卡 · 次卡），粗门次卡也算一档，整卡和它的卡种不能分到两档，不同卡种之间可以各占一档。客户买过靠前的大类、第一次进靠后的大类时，那笔成交记成「升单」，购买类型里可以单独筛它；升单人按客户去重（一个客户只算一次），升单量按次数累加（同一人多次升单计多次）。
- 复购按所选产品范围；交易列表按产品大类。同类复购＝同一大类里同一个具体项目（会员卡按卡种区分，换了卡种算跨品类首购）；跨品类首购不计同类复购。
- 398 会员应选对应具体卡种，不使用实际成交金额匹配，避免折扣、赠送造成误判。
- 粗门扣卡依据仍有效的扣卡记录、对应课程名单与实际到场确认，仅作为使用事件；使用次数不等于购买次数。
- 到场基于邀约已到场加课程参与/案主名单，排除退课。首次/再次到场按可见课程历史，不用当前会员身份倒推历史身份。
- 课时沿用现有课程扣卡课时口径，不按开始/结束时间换算。
- 课程所属优先课程/活动类型配置；没有配置时只在老师唯一所属组织时回退。缺失或有歧义的归属不猜测、不重复计课。交易按成交归属；无成交日期、删除、作废或无可见归属的订单不参与。
- 后续交易按观察天数、同组织与参与人关联，同一订单可能与多节课相关，不代表独占归因，不应将各课关联笔数相加当作总交易笔数。

## 保存、导出与日志

- 规则保存在独立 PostgreSQL JSON 存储表 `principal_rules`，由现有存储机制首次访问时初始化，重启不丢失。
- 规则默认私有，也可设置为共享并添加说明。普通账号只能修改/删除自己创建的规则；共享规则可引用或另存，超级管理员可管理全部规则。删除为软删除，不删除业务数据。
- PC 与小程序共享规则，支持仅本次计算、保存更新和另存。
- 导出当前筛选的全部行及关联明细，不限当前分页；内容自动换行并防止公式注入。
- 规则新增/修改/删除和导出写入「主理人」操作日志；页面访问/使用时长沿用现有使用统计。
