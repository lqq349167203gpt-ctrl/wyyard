# 小程序读取性能同步

本次范围已实现：复用上一轮后端读取优化，不改页面设计、扣卡及交易口径；不修改业务数据、不提交或发布。保留其他协作者已有改动。

## 管理端

| 位置 | 已实现的调整 |
| --- | --- |
| 共用请求 | 同账号、权限、页面和条件的在途 GET 合并；完成、失败、业务写入及重登后释放。写入、心跳、导出日志不合并。登录重试绕开在途键，避免等待自身。 |
| 客户列表 | 每页 20 条；新筛选可以立即请求，旧响应不能覆盖；仍使用带余量的原列表接口。引流人选项取完整可见轻量目录，不取当前页。 |
| 客户搜索 | 筛选目录使用轻量客户接口，避免为选项计算整页会员卡余量；搜索与筛选继续服务端执行。 |
| 邀约 | 切日期不再排队等待旧日期；保留轻量读取、排序迁移及返回页滚动恢复；过期响应不落入当前列表。 |
| 课表 | 现有日期/空间过期响应保护保留，共用目录及重复读取可用在途合并。 |
| 沟通记录 | 列表和搜索共享一个分页实现；昵称/姓名、多个创建人筛选在分页前执行。创建人选项及排序人数来自完整可见集合。编辑只取单条记录。 |
| 每日报表 | 客户、身份及五类课表来源通过按日接口合并，普通内容不等待财务；财务按需读取当天相关人员所需历史，不下载无关人的历史。失败明确提示重试，不伪装成零笔或未办卡。切日期及关闭详情后不接收旧结果。 |
| 组织/俱乐部 | 成交列表和概况一次查询；手机分页复用已脱敏的同条件统计。缓存条件含账号、角色权限、手机板块、业务数据版本及当天日期，业务写入后失效。保留原手机裁剪与全量老师跟进统计。 |

日报首次入口按源码计数由至少 17 个业务读取降为 5 个；这是请求数量对比，不是网络耗时测试。普通内容只需合并来源与日历两个读取完成。原同步课表计算仍在线程池中运行，不因合并而阻塞其他异步接口。

组织统计缓存继续沿用原机制：15 秒、最多 8 个结果、明细最多 10000 行；进程内复用，不缓存失败或导出，不代替持久化和后端权限判断。

## 客户端

仅为客户端自身的 GET 增加同会话在途合并；请求完成及写入后释放。没有引入管理端报表/沟通接口，也没有改客户端登录、展示或业务数据。

## 验证与发布边界

- 7 项实际 JavaScript 执行测试：两端请求去重及写入失效、分页失败重试、筛选完整性、日报分段读取及权限、客户与邀约异步切换。
- 后端 84 项定向回归通过；日报线程池调整后额外复核相关 2 项通过。测试仅使用本机 PostgreSQL 的 `wyyard_test` 隔离 schema。
- 本次 11 个 JavaScript 文件语法、两端项目与页面 JSON、管理端修改页面注册检查通过。
- 微信开发者工具附带 WXML 编译器：日报、沟通列表和沟通搜索模板通过；未进行真机交互或正式服务器性能验收，不承诺 100 毫秒。
- 两端原数据源不变，当前都指向正式服务器。本次未对正式接口发起业务测试。
- 上线先更新后端，再重新编译、上传管理端；客户端请求层变更也需要重新编译、上传客户端。Git 推送、后端部署及微信发布尚未执行。

## 每日报表日期与来源修正

- 管理端课表、邀约、日报共用日期读写工具。日报返回时先同步选中日期，再按该日期读取；日报选择日期也同步其他两个入口，不再只写旧的邀约日期键。
- 后端将课表已有的五类当日课程读取提取为共享函数，保留日期、空间及客户可见范围处理。两端日报使用同一展示列表，并返回数据日期；活动名称优先使用实际录入名称。
- 日报不调用完整课表 dashboard，不扫描历史日历、分组或课程填写进度。原始课程仍用于现有销卡计算，避免五类展示列表导致重复计数。
- PC 普通内容只有在数据日期与所选日期一致且读取成功时显示。加载及失败状态不再在新日期下显示旧客户、旧课程和旧计数，导出继续保持相同约束。
- 本轮定向回归覆盖五类来源、空间/客户范围、退课、快速日期切换、返回日报、错误界面及销卡来源不重复；PC 构建与管理端日报 WXML 编译通过。未做正式服务器或真机验收，数据源保持不变。
