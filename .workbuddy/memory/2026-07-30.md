# 2026-07-30

## 修复：引流统计/服务数据页会员类型筛选无效

**根因**：两个页面的会员类型（和引流人）筛选按钮只做前端过滤，且仅作用于底部明细列表；上方汇总卡片和图表来自后端聚合接口，接口不支持这些筛选参数 → 点击后页面综合数据无变化，用户感知"筛选没用"。

**改动**：
- 后端 `backend/app/api/statistics.py`
  - `/api/statistics/referrals` 新增 `member_types`（逗号分隔多选）参数，先过滤客户再聚合；返回新增 `member_type_names` 全量选项（防选项塌缩）
  - `/api/statistics/overview`、`/api/statistics/details` 新增 `member_types` + `referrer` 参数；邀约/到访按 visit.referrer_handler 过滤，成交按 customer.referrer 过滤（沿用前端原有语义）；details 返回全量 `member_type_names`/`referrer_names`（过滤前收集）
  - 新增 `_parse_member_types` / `_sort_member_type_names`（按身份配置倒序）/ `_normalize_query_str`（兼容直接调用时 Query 对象默认值）
  - 顺带修复潜在 bug：`_aggregate_member_cumulative` 在筛选结果为空时 KeyError 崩溃（原本选无客户的引流人也会触发）
- 前端
  - `api.ts`：三个接口加参数；`ReferralStatistics` 加 `member_type_names`；details 返回类型加可选 `member_type_names`/`referrer_names`
  - `referral-statistics/index.tsx`：选项改用后端全量 `member_type_names`；selectedTypes 变化触发后端重新请求；移除前端列表过滤
  - `statistics/index.tsx`：typeNames/referrerNames 改为 state（来自后端响应）；fetchData/fetchDetails 传筛选参数；移除 sortedDetails 中的前端会员类型/引流人过滤
