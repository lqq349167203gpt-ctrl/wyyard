# 验证与收尾

授权、数据安全、Git 和完成标准见根目录 AGENTS.md。使用现有本地依赖，从对应目录执行检查。

## 检查范围

先按差异选择能覆盖风险的最小检查集合。连续小改合并到稳定后验证；失败后只重跑失败项和受修复影响的项。代码、依赖、配置及相关环境未变时复用已通过结果，不为收尾或提交重复运行。

| 改动 | 必要检查 |
|---|---|
| 文档、Skills、静态预览 | 差异、引用、语法及适用的展示检查；不跑业务构建或数据库测试 |
| 纯样式、固定文案 | 核对本次展示与差异；涉及编译语法、生成样式或资源引用时补构建，不跑无关业务测试 |
| frontend/ 逻辑、依赖或构建配置 | 稳定后一次 npm run build（含 tsc -b），按风险补关键交互，不重复类型检查 |
| backend/ 局部业务 | .venv/bin/python -m pytest 定向到用例/测试文件；.venv/bin/ruff check 修改的 Python 文件 |
| 鉴权、扣卡/退费、共享持久化或依赖删除 | 定向回归及必要集成检查；无法据影响范围选出可靠子集或用户要求时才跑完整 pytest，扩大前简述原因 |
| 小程序源码 | 修改 JS 的 node --check、JSON 解析、注册和接口核对；开发者工具可用时编译并检查关键交互，不用 PC 构建替代 |
| 准备提交源码 | 复用已通过的对应检查，核对暂存差异及敏感文件；删除/迁移组件、调整依赖或清理代码时才按需运行 bash scripts/check-dead-code.sh |

- 修 bug 优先增加复现根因的回归；纯样式/文案不写只匹配实现字符串的测试。
- 数据库测试前读 conftest，核实连接目标与隔离措施。工具缺失先尝试现有运行时/venv。
- 独立只读检查可并行；共用测试库/schema、文件或服务状态的测试不并行。输出优先简短摘要（如 pytest -q --tb=short），只展开失败项。
- 用户限制验证时如实记录未验证范围；无开发者工具不宣称真机已验。

## 失败判断

- 本次引入或直接相关：修复后重跑，不删断言、skip 或用 any 掩盖失败。
- 确认无关的旧失败：提供修改前或对照证据，不扩展为全仓修复。
- 环境受阻或归属未知：做安全替代检查和最小诊断，明确剩余风险，不称验证通过。
- 冗余脚本需阅读输出：退出码 0 不代表全部检查执行；非零需区分新增缺陷、历史问题和合法兼容保留，不为凑全绿删除文件。

相关检查通过且无新改动或未解决风险后收尾，简述实际验证结果与剩余项。
