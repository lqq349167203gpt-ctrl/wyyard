## 导出 500 根因修复
- 用户切到本地（DEV=true + BASE_URL 改局域网 IP 192.168.31.141:8000）后仍「导出失败」。
- 端到端排查（dev-login 拿 token → 注意 **dev-login 不注册 session，会被 jwt 中间件按 kicked 拦 401**，需手动 create_session 才能测）：导出接口返回 **500**。
- **根因**：`StreamingResponse` 的 `Content-Disposition` 直接写中文文件名「邀约到场_日期.xlsx」，HTTP 头只支持 latin-1 → `UnicodeEncodeError` → 500。
- **修复**（`564dfc7`）：改 RFC 5987 `filename*=UTF-8''<quote>` + ASCII 兜底文件名；同时发现 **openpyxl 只在本地 venv 手动装过、没进 pyproject.toml**，已补依赖声明（否则生产部署后同样 500）。
- 修复后实测：HTTP 200、6225 bytes、xlsx 内容正确（19 条记录、9 列表头）。生产使用仍需 push + 部署。
- 导出文件名按用户要求改为 **`2026年7月29日邀约名单.xlsx`**（无日期时「全部邀约名单.xlsx」），`6bb81bb` 已提交。sheet 内页名仍叫「邀约到场」（对齐 PC 端，未动）。至此本地 3 个待部署 commit：6435932 / 564dfc7 / 6bb81bb。

## 导出文件名"乱码"修复
- 用户反馈导出的文件名是乱码。根因：`wx.downloadFile` 存的是**随机临时文件名**（tmp_xxx），`openDocument` 打开/转发显示的就是它，后端 Content-Disposition 文件名传不到小程序侧。
- 修复（`8d390d5`）：`onExportTap` 下载成功后用 `FileSystemManager.rename` 把临时文件重命名为「年月日邀约名单.xlsx」（存到 `wx.env.USER_DATA_PATH`）再 openDocument；同名旧文件先 unlink，rename 失败降级直接开临时文件。
